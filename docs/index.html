3. Đối chiếu 5 đặc tính NIST

01 / NIST

On-demand Self-service

Tự tạo Codespace bằng Create codespace on main mà không cần người quản trị cấp máy thủ công.

02 / NIST

Broad Network Access

Truy cập API qua HTTPS từ trình duyệt máy tính và điện thoại khi cổng 3000 được đặt Public.

03 / NIST

Resource Pooling

Sử dụng tài nguyên từ hạ tầng được GitHub quản lý và phân phối cho nhiều người dùng, không cần quản lý máy chủ vật lý.

04 / NIST

Rapid Elasticity

Có thể tạo, dừng, khởi động lại Codespace và thay đổi cấu hình máy khi dịch vụ cho phép. Bài thực hành chưa đo tự động co giãn theo tải.

05 / NIST

Measured Service

GitHub đo tài nguyên theo mức sử dụng. Ảnh Usage breakdown của repository notes-api-2324802010360 ghi Gross $0.39, Billed $0.00, trong đó Codespaces compute 2-core sử dụng 0.55 giờ với Gross $0.10.

5. Câu hỏi phản biện

1. Trường host có thay đổi khi Stop rồi Start Codespace?

Trường host có thể giữ nguyên hoặc thay đổi tùy cách GitHub cấp phát môi trường. Việc giữ nguyên hay thay đổi hostname không đủ để chứng minh hoặc bác bỏ Resource Pooling. Đặc tính này nói về việc nhà cung cấp quản lý và phân phối tài nguyên từ hạ tầng dùng chung. Muốn kết luận cho lần thử cụ thể, cần ghi kết quả host trước và sau khi Stop/Start.

2. Codespaces thuộc IaaS, PaaS hay SaaS?

Codespaces là môi trường phát triển được quản lý, có nhiều đặc điểm gần với PaaS: GitHub quản lý hạ tầng và việc cấp phát, còn sinh viên quản lý mã nguồn, thư viện và cấu hình ứng dụng. Giao diện IDE trên web có đặc điểm SaaS; đây không phải máy ảo IaaS thuần túy do người dùng tự quản trị toàn bộ.

3. Hai hạn chế truyền thống và một rủi ro mới?

Codespaces giảm thời gian cài đặt môi trường trên từng máy phòng lab và giảm phụ thuộc vào một thiết bị vật lý. Rủi ro mới là phụ thuộc Internet, khả năng phát sinh chi phí và nguy cơ lộ dữ liệu nếu công khai cổng hoặc commit bí mật lên repository Public.

6. Kết luận

Bài thực hành giúp trải nghiệm việc cấp phát môi trường phát triển trên đám mây, viết API với Express, truy cập dịch vụ qua mạng và quan sát việc đo lường tài nguyên. Sau khi kiểm thử công khai, cần chuyển cổng 3000 về Private và Stop Codespace để bảo đảm an toàn, tiết kiệm hạn mức.

Trang GitHub Pages này là website tĩnh nên vẫn xem được khi API Codespaces đã dừng. Khi Codespace đã Stop hoặc cổng Private, tính năng gọi API trực tiếp trên Pages sẽ không hoạt động công khai.

LAB 02 – Container và CloudSim Plus

Bài thực hành đóng gói Hello Cloud API bằng Docker, triển khai nhiều container, giới hạn tài nguyên, phát hành image lên GHCR và mô phỏng trung tâm dữ liệu bằng CloudSim Plus.

1. GitHub Container Registry

Package: thongfank/notes-api 

docker pull ghcr.io/thongfank/notes-api:1.0

2. Dockerfile

FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY src ./src
ENV PORT=3000
EXPOSE 3000
USER node
CMD ["node", "src/server.js"]

6. Câu hỏi phản biện

Câu 1. Vì sao API vẫn báo RAM của máy chủ?

Hàm os.totalmem() có thể báo dung lượng bộ nhớ của hệ thống thay vì giới hạn cgroups của container. Vì vậy, ứng dụng Node.js hoặc Java cần nhận biết giới hạn tài nguyên thực tế và cấu hình bộ nhớ phù hợp để tránh bị hệ điều hành kết thúc khi vượt quá giới hạn RAM.

Câu 2. TimeShared và SpaceShared khác nhau thế nào?

TimeShared cho phép nhiều Cloudlet chia sẻ CPU theo thời gian. SpaceShared yêu cầu đủ tài nguyên trước khi Cloudlet được thực thi, do đó có thể phát sinh thời gian chờ. Nhà cung cấp dịch vụ có thể sử dụng TimeShared cho gói giá rẻ nhằm nâng cao hiệu suất sử dụng tài nguyên.

Câu 3. Lợi ích và hạn chế của mô phỏng là gì?

Mô phỏng giúp đánh giá cấu hình tài nguyên và chính sách lập lịch trước khi thuê hạ tầng thật. Tuy nhiên, kết quả có thể khác thực tế do độ trễ mạng, I/O, lỗi phần cứng và sự biến động tải.
